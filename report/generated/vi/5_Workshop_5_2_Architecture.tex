\vspace{0.5em}\noindent\textbf{Kiến trúc}\par

\vspace{0.5em}\noindent\textbf{Mục tiêu}\par

Chương này mô tả kiến trúc AWS cuối cùng và các luồng chạy chính của hệ
thống Internship Application Tracker.

\vspace{0.5em}\noindent\textbf{Phạm vi}\par

Kiến trúc được viết dựa trên ngữ cảnh production đã cung cấp, ghi chú
trong repository Report và repository ứng dụng hiện tại. Bằng chứng
runtime được ưu tiên hơn các manifest cũ. Điểm chỉnh quan trọng nhất là
frontend hiện được phục vụ bằng S3 và CloudFront, không chạy như một
workload trong EKS.

\{\{\textless{} mermaid \textgreater\}\} sequenceDiagram participant

\end{verbatim}

\vspace{0.5em}\noindent\textbf{Diagram 4: Luồng realtime
chat}\par

\{\{\textless{} mermaid \textgreater\}\} sequenceDiagram participant
UserA as User A browser participant CF as CloudFront participant ALB as
ALB participant Chat1 as chat-service pod A participant Redis as
ElastiCache Redis participant Chat2 as chat-service pod B participant
DDB as DynamoDB chat tables participant UserB as User B browser

\begin{verbatim}
UserA->>CF: Socket.IO connect /socket.io
CF->>ALB: Forward websocket/polling traffic
ALB->>Chat1: Route to chat-service

Chat1->>DDB: Persist message

\end{verbatim}

\{\{\textless{} /mermaid \textgreater\}\}

DynamoDB là nơi lưu trữ chat lâu dài. Redis chỉ là lớp pub/sub giữa
nhiều pod và không thay thế persistent storage.

\vspace{0.5em}\noindent\textbf{Diagram 5: Luồng transactional outbox, SQS và
Lambda}\par

\{\{\textless{} mermaid \textgreater\}\} sequenceDiagram participant API
as FastAPI backend participant PG as RDS PostgreSQL participant
Dispatcher as Outbox dispatcher participant SQS as SQS main queue
participant Lambda as Lambda outbox handler participant DDB as DynamoDB
dedupe participant S3 as S3 archive bucket participant SES as Amazon SES

\begin{verbatim}
API->>PG: Commit business mutation and outbox_events row in one transaction
Dispatcher->>PG: Claim pending outbox_events row with lease
Dispatcher->>SQS: Send event envelope
Dispatcher->>PG: Mark event PUBLISHED
SQS->>Lambda: Invoke batch
Lambda->>DDB: Conditional write eventId
alt First time event
    Lambda->>S3: Put JSON archive
    Lambda->>SES: Send email notification
else Duplicate event
    Lambda-->>SQS: Treat as already processed
end
\end{verbatim}

\{\{\textless{} /mermaid \textgreater\}\}

SQS có cơ chế at-least-once delivery. Duplicate delivery là tình huống
bình thường, vì vậy Lambda phải xử lý idempotency. Smoke test thành công
có event \texttt{lambda-\allowbreak{}smoke-\allowbreak{}fixed-\allowbreak{}1785220478}, được archive tại
\texttt{outbox-\allowbreak{}archive/\allowbreak{}2026/\allowbreak{}07/\allowbreak{}28/\allowbreak{}lambda-\allowbreak{}smoke-\allowbreak{}fixed-\allowbreak{}1785220478.\allowbreak{}json}.

\vspace{0.5em}\noindent\textbf{Ranh giới bảo mật}\par

\begin{itemize}
\tightlist
\item
  GitHub Actions dùng OIDC để assume role
  \texttt{internship-\allowbreak{}github-\allowbreak{}deploy}.
\item
  EKS workloads dùng ServiceAccount \texttt{internship-\allowbreak{}app} và IRSA role
  mapping.
\item
  Secrets được inject qua GitHub environment secrets và Kubernetes
  \texttt{internship-\allowbreak{}secrets}.
\item
  S3 frontend bucket phải giữ private và chỉ cho CloudFront đọc.
\item
  Backend và chat pods chỉ expose service ports qua ALB path rules.
\item
  AI traffic đi nội bộ trong cluster từ worker đến \texttt{ai-\allowbreak{}service};
  SageMaker được gọi bởi adapter.
\item
  SQS/Lambda processing xử lý idempotency bằng DynamoDB conditional
  writes.
\end{itemize}

\vspace{0.5em}\noindent\textbf{Kết quả mong đợi}\par

Kiến trúc cuối cùng tách rõ static delivery, public request routing,
long-running service execution, transactional storage, realtime
synchronization, asynchronous event delivery, short event-driven
notification và AI inference. Mỗi thành phần có trách nhiệm rõ ràng và
có đường kiểm tra độc lập.
