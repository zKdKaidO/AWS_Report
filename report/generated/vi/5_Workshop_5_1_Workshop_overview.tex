\vspace{0.5em}\noindent\textbf{Scope}\par

The workshop covers the current production architecture only. The
frontend is hosted on Amazon S3 and CloudFront. It is not documented as
an EKS Deployment because the old Kubernetes frontend Deployment,
Service, HPA, and PDB were removed.

The EKS cluster hosts these long-running workloads:

\begin{itemize}
\tightlist
\item
  \texttt{backend}
\item
  \texttt{chat-\allowbreak{}service}
\item
  \texttt{backend-\allowbreak{}outbox-\allowbreak{}dispatcher}
\item
  \texttt{backend-\allowbreak{}processing-\allowbreak{}worker}
\item
  \texttt{ai-\allowbreak{}service}
\end{itemize}

The managed AWS services connected to the application are RDS
PostgreSQL, DynamoDB, ElastiCache Redis, S3, SQS, Lambda, SES,
SageMaker, CloudFront, ALB, ECR, IAM, and CloudWatch.

\vspace{0.5em}\noindent\textbf{Architecture context}\par

The browser reaches CloudFront first. CloudFront routes static frontend
requests to a private S3 bucket and routes dynamic paths to the
Application Load Balancer:

\begin{itemize}
\tightlist
\item
  Default \texttt{*} -\textgreater{} S3 frontend bucket
\item
  \texttt{/\allowbreak{}api/\allowbreak{}*} -\textgreater{} ALB -\textgreater{} FastAPI backend
\item
  \texttt{/\allowbreak{}chat/\allowbreak{}*} -\textgreater{} ALB -\textgreater{} chat service
\item
  \texttt{/\allowbreak{}socket.\allowbreak{}io/\allowbreak{}*} -\textgreater{} ALB -\textgreater{} chat service
\end{itemize}

PostgreSQL stores transactional business data and worker queues.
DynamoDB stores chat records and Lambda dedupe records. Redis provides
Socket.IO pub/sub between chat pods. SQS decouples committed business
events from Lambda processing. Lambda archives events to S3 and sends
email through SES. The processing worker calls \texttt{ai-\allowbreak{}service},
which invokes the SageMaker endpoint \texttt{internship-\allowbreak{}qwen3-\allowbreak{}4b}.

\vspace{0.5em}\noindent\textbf{Functional scope}\par

The application supports:

\begin{itemize}
\tightlist
\item
  candidate and HR authentication
\item
  job posting and job search
\item
  candidate application submission
\item
  application workflow management
\item
  CV and document upload
\item
  asynchronous CV parsing, job parsing, and matching
\item
  realtime chat between users
\item
  transactional outbox event publication
\item
  email notification through Lambda and SES
\end{itemize}

The technical implementation includes:

\begin{itemize}
\tightlist
\item
  React and Vite frontend
\item
  FastAPI backend
\item
  Node.js, Express, and Socket.IO chat service
\item
  PostgreSQL with Alembic migrations
\item
  DynamoDB chat tables
\item
  Redis Socket.IO adapter
\item
  EKS Deployments, Services, HPA, PDB, ServiceAccount, ConfigMap,

\item

\item
  CloudFront distribution with S3 and ALB origins
\item
  SQS Standard queue and DLQ
\item
  Lambda event consumer with DynamoDB idempotency
\item
  SageMaker inference endpoint behind an internal AI adapter
\item
  GitHub Actions CI/CD using AWS OIDC
\end{itemize}

\vspace{0.5em}\noindent\textbf{Prerequisites}\par

The reader should have authorized access to the AWS account, GitHub
repository, EKS cluster, and production deployment settings. Exact tool
versions must be verified in the target environment unless documented by
the repository workflow.

\vspace{0.5em}\noindent\textbf{Implementation flow}\par

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Review the source repository and deployment scripts.
\item
  Confirm AWS account, region, IAM, and GitHub OIDC configuration.
\item
  Provision or verify AWS infrastructure.
\item
  Deploy RDS, Redis, DynamoDB, S3, SQS, Lambda, SageMaker, and
  CloudFront resources.
\item
  Build and push backend, chat, and AI images to ECR.
\item
  Deploy backend, chat, dispatcher, worker, and AI adapter to EKS.
\item
  Build the Vite frontend and publish it to S3.
\item
  Invalidate CloudFront.
\item
  Run health checks and end-to-end acceptance tests.
\item
  Monitor logs, metrics, and alarms.
\item
  Troubleshoot incidents using evidence.
\item
  Clean up resources in dependency order when the environment is no
  longer needed.
\end{enumerate}

\vspace{0.5em}\noindent\textbf{Expected result}\par

After a successful deployment:

\begin{itemize}
\tightlist
\item
  CloudFront serves the frontend.
\item
  \texttt{/\allowbreak{}api/\allowbreak{}health/\allowbreak{}ready} reaches the FastAPI backend.
\item
  \texttt{/\allowbreak{}chat/\allowbreak{}health/\allowbreak{}ready} reaches the chat service.
\item
  Socket.IO connects through \texttt{/\allowbreak{}socket.\allowbreak{}io}.
\item
  PostgreSQL, DynamoDB, Redis, SQS, Lambda, SES, S3, and SageMaker are
  integrated.
\item
  GitHub Actions can run validation and deployment workflows through
  OIDC.
\item
  The system can process business events and archive Lambda output.
\end{itemize}

AI inference.
